# Aura Vault

A static, mobile-first Pokémon TCG collection tracker with a premium dark gaming interface. Open `index.html` in a current browser; no build step or backend is needed. The interface is designed for iPhone/iPad Safari, with a safe-area-aware mobile bottom navigation and a desktop sidebar.

The Aura Vault icon is stored locally as `aura-vault-logo.png` and is used in the app header, browser tab, and iOS home-screen icon.

## Data sources and behavior

- **Pokémon selector:** [PokéAPI National Pokédex endpoint](https://pokeapi.co/api/v2/pokedex/1) provides each species' explicit National Pokédex entry number. Type a Pokémon name into the collection selector and choose its suggestion (or press Enter); the full list is cached locally, and card records are fetched only for the selected Pokémon so the app does not download the entire TCG database at startup.
- **Card catalog, set/card metadata, set logos, and card images:** [Pokémon TCG API v2](https://api.pokemontcg.io/v2/cards), queried for the selected Pokémon. The set filter is populated from that Pokémon's returned cards. Artwork and available set-logo URLs are used directly from the API (normally hosted at `images.pokemontcg.io`); image colors and proportions are not altered.
- **Set card numbering:** card numbers include the API's set `printedTotal` where available (for example, `4/102`). Secret or special cards may have a number higher than the printed total, matching their printed numbering.
- **Card scanner:** the Scan Cards dialog requests a rear-facing camera when supported and offers upload as a fallback. Captures remain in memory only; image rotation and centered cropping are non-destructive, and the original image stays available during that scan. Brightness, glare, small-image, and focus warnings are approximate hints, never hard rejection. [Tesseract.js](https://github.com/naptha/tesseract.js) performs on-device English OCR; the library and language model load from public CDN endpoints. OCR card-number and printed-set-total text can rank live Pokémon TCG API catalog candidates; a missing catalog total is not reported as a complete number match. Candidate explanations describe text evidence, not measured confidence or image similarity. No card is auto-selected; confirm each catalog result and the queue's printing, language, condition, quantity, acquisition method, seller/source, price, and date before adding. Existing copies with matching print, language, and condition are warned about but may still be added. Manual catalog search is available when OCR fails. Camera permission and HTTPS (or localhost) are required for live camera access; unsupported browsers, denied permissions, and missing cameras can use image upload. Camera tracks stop when the scanner closes. No AI service, private API key, backend, perspective correction, or image-similarity score is used; those would require a separately configured and reviewed detector/service. The catalog API/CDN must be reachable and permit browser CORS requests.
- **Market estimates:** the API's `tcgplayer.prices[variant].market` value, shown in USD. This is an API-provided TCGplayer market estimate, not a real-time sale quote. The app marks values stale when the supplied price update is more than seven days old, and shows unavailable rather than substituting a hardcoded or guessed value.
- **TCGplayer listings:** the card price sheet opens a TCGplayer search prefilled with the selected card, set, number, treatment, and Pokémon TCG. Confirm the exact printing and condition in the results. The Pokémon TCG API supplies market estimates, but not a TCGplayer product ID for reliable exact-product links.
- **PriceCharting and eBay:** select a card's artwork/details to open its price sheet. The sheet shows the available TCGplayer estimate and builds searches for the selected card, set, number, treatment, and Pokémon TCG. PriceCharting opens a price-guide search; eBay has completed/sold and current-listing searches. These external results open in new tabs and are not scraped, imported, or represented as app-verified prices. Both sites can return imperfect matches, so confirm the exact printing and condition.
- **Why external price results open in another tab:** PriceCharting and eBay do not expose these searches as a safe, anonymous browser-price feed for this static app. PriceCharting's API access and eBay's Browse API require their own supported access/authentication. Putting private API credentials in client-side JavaScript would expose them, and scraping their pages from the browser is not reliable (CORS, site policies, and changing markup). To show their returned numeric quotes inside the app, add a backend/proxy that securely stores credentials and follows each provider's terms/rate limits.
- **Authentication, CORS, and rate limits:** the Pokémon TCG API supports unauthenticated requests with lower rate limits than keyed requests. Its actual limits can change; this app fetches a selected Pokémon on startup or selection and follows paginated results. Catalog requests retry transient network, timeout, rate-limit, and server errors up to three times, with bounded backoff and request timeouts. A per-Pokémon cache keeps the four most recently refreshed catalogs, displays the selected Pokémon's saved cards while updating, and automatically retries when the browser reconnects. The app calls public APIs from the browser, so it still depends on the Pokémon TCG API allowing browser CORS requests; retries cannot work around an upstream outage or CORS policy failure. The species list and catalog cache are local to the browser.
- **Verified vs. unverified data:** catalog entries display source verification when the API supplies a name, set, and number. Missing prices are called out independently. Custom treatments (for example, a local league stamp notation) are explicitly user-entered and cannot be verified by the API. The API search is a practical catalog source, not a guarantee that every historical language, print variant, staff/judge distribution, or stamp is represented.
- **Local data and offline use:** collection entries, wishlist, monthly expenses, budget, favorites, saved product links, the Pokémon species list, and recent catalog metadata are stored in this browser's `localStorage`; card artwork and catalog price estimates still need network access. No collection data is sent to an app backend.
- **Backup compatibility and restore:** export downloads a versioned JSON backup of the existing `lucario-ledger.data.v1` data, including per-copy purchase details, wishlist goals, favorites, spending, budget, and custom product links. Import validates the entire file and previews its record counts before writing. **Merge** is the safe default: it adds non-duplicate records and preserves existing settings/records. **Replace** is available only after a checkbox and a second confirmation. Invalid backups are rejected without modifying the vault. If saved data cannot be parsed, writes and exports are blocked rather than silently overwriting it; a valid backup can be explicitly restored with Replace.

## Collection details

Owned entries track print treatment, per-copy condition, language, acquisition method, price, date, seller/source, storage, binder slot, and optional official grading details. The Add to Collection workflow starts from an exact catalog-print picker or card action, prefills editable catalog metadata, shows official card art and the available estimate, and lets each copy record its own condition and cost. Records keep distinct catalog card IDs, language, and print treatments separate; multiple copies and condition groups are preserved. When a matching print, treatment, condition, and language are already owned, the form warns before allowing additional physical copies to be recorded. Optional grading company, grade, and certification fields are saved as user-entered official-label details; Aura Vault never estimates grades. Add & add another keeps the workflow ready for another entry. Card details show acquisition cost separately from the available estimated market value. The Owned tab aggregates owned prints across Pokémon, using saved local catalog caches and fetching missing card details by ID when online; if the source is unavailable, saved entries remain visible with an unavailable-details notice. Catalog browsing supports search, Pokémon context, set, rarity, language, promotional/stamp treatment, condition, owned/missing status, favorites, wishlist, and sorting; the matching count and Clear filters control update with the results. Filters such as condition and Pokémon are shown only when the loaded/saved card records can support them.

The dashboard reports collection progress for the selected catalog and by set when catalog data is available. Set progress uses the catalog's official set logo where provided and is laid out in separate cards; owned prints have a compact check indicator on their artwork. The Wishlist tab aggregates saved cards across Pokémon, regardless of the selected Pokémon. Wishlist entries can have an optional target price and low/normal/high priority; comparisons use the Pokémon TCG API market estimate when present and clearly mark stale or unavailable quotes. These estimates are not guaranteed real-time prices. The Wishlist reuses local catalog caches and remembers resolved card details for offline access; if details cannot be resolved, the saved ID and treatment remain visible with an unavailable-details notice.

On a phone, choose **Scan card**, allow camera access, and capture a clear upright card with its name visible. Select the matching printing from the results before saving it. OCR needs a network connection the first time to download its library/model, and catalog matches require the Pokémon TCG API to be reachable.

## Pokémon and set browsing

The selector lists species from PokéAPI's National Pokédex, ordered and labeled by its explicit entry number (for example, `#1 Bulbasaur`). Choosing a Pokémon queries its card records from the Pokémon TCG API; the set/collection filter then narrows those records. The full multi-Pokémon card database is intentionally not preloaded: card count and regional, promotional, and language coverage depend on the TCG API. Set logos display when that API provides a logo URL. The selected-Pokémon catalog and selector list are cached locally for offline metadata browsing.
